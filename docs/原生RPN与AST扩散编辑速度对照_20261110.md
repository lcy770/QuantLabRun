# 原生 RPN 与 AST 扩散编辑速度对照

日期为 2026-11-10。本轮执行用户指定的原生 RPN 编辑与速度比较。

## 当前结果

完整30秒搜索中，原生 RPN 相对优化后 AST 的完成候选吞吐比为 1.073，相对同权重 RPN 树编辑后端为 1.086。比值大于1表示原生 RPN 更快。具体差异需要结合下方固定尝试和微基准阅读。

速度排序随场景变化。两步推理冷缓存的完整扰动及去噪，优化后 AST 为 52.216 毫秒/候选，原生 RPN 为 29.078 毫秒/候选，耗时降低 44.3%。四步训练录制预热场景的均值则为 AST 12.540 毫秒、原生 RPN 51.615 毫秒，AST 更快。

本轮复用此前三个配对模型种子的已训练权重，原生 RPN 通过等价动作空间迁移。新增的正常入口测试实际运行了下层 PPO、概率重放、保存恢复和双进程采集。当前工作属于工程编辑速度验证，金融指标使用已反复研究的开发时期。

两种编码器宽度均为32，下层参数量分别为 AST 18,307、RPN 24,835。本轮真实搜索模型使用上一轮表示对照的条件设置，持续任务条件和位置向量均为关闭。相关开启分支另由回归测试覆盖。

## 原生路径与改动

RPN 后端使用整数 token 序列、栈扫描得到的子表达式区间、原生合法位置和替换掩码、token 区间拼接及原生逆向标签。数值和类型检查共享算子语义规则。去噪编辑核经测试可在禁用 AST 的编辑、替换、扰动及 validate 入口后运行，包含录制和概率重放。

现有公式库及金融求值接口使用 Node 序列化，入口和终点边界执行转换。原生后端在内存及二进制训练轨迹中保留 RPNProgram 和 TokenEdit，PPO 重放直接使用 token。人读日志在写出边界转换表达式，额外记录真实 token 编辑区间。

优化包含局部语义及无效子式缓存、增量祖先验证、虚拟扁平动作序号的均匀拒绝采样、结构文本与哈希缓存、去重后的 GRU 序列、直接补齐批处理、替换候选和 Critic 的根序列编码，以及原生训练轨迹。

AST 同时采用了适用的均匀采样与缓存优化。新拒绝采样在合法非保持动作上的分布与旧枚举采样一致，随机数消耗顺序有变化。旧 AST 源码作为单独冻结对照保留。

### 四步录制预热的慢点

该场景九组设置的中位耗时为 AST 9.842 毫秒/候选、原生 RPN 9.671 毫秒/候选。原生均值受两组明显慢点影响。

在事后选择的两个慢点中检查完整动作缓存。种子1、采样202的RPN轨迹请求48,794条动作条目，重复一遍只有1/52次完整动作查询命中缓存。种子2、采样202请求45,066条，只有2/52次命中。两组AST对照分别为52/52次命中。当前完整动作缓存上限为40,000条，出现容量淘汰和重复构建。同权重RPN树后端也出现对应的缓存命中模式。

上述诊断是两组慢点的事后样本。它定位了训练录制工作集的缓存瓶颈，当前速度数据保留该实现的实际表现。

## 结论范围

结果适用于本机CPU、单Torch线程、当前公式规模、编码器和两种编辑步数。热缓存是重复同一公式批的情形。不同设备、公式长度、编辑预算及缓存命中率可能改变排序。三个模型种子与重复采样的结果按各自依赖关系报告。

首版原生实现曾慢于树后端，相关剖析和逐轮小样本保留。第一轮288组基准及36次固定验证发现录制轨迹转换旧对象的额外开销，完整结果和源码另存 v1_before_native_recording_optimization。修复为原生轨迹后按同协议重新运行。

首轮固定次数启动还遇到 Windows PowerShell 5 将只读 NumPy 警告作为 NativeCommandError 停止编排。六份已完成结果保留，所属等待子进程清理后恢复完成。启动脚本改为独立收集 stdout、stderr 并检查退出码。该轮尚未开始正式限时计时，恢复记录另存。

此前1.2至2倍的原生RPN提速估计属于工程预测，实际结论以上述数据为准。搜索达标、后续达标和组合增量分别记录。本轮尚未验收整体双层算法的金融优势。云费用为0元。
